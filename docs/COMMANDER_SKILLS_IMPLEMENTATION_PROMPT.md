# Commander Skills redesign implementation prompt

Rebuild Commander → Skills in Forged Alliances TD 0.8.3 using the approved Commander Skills mockup as the desktop and landscape tablet reference. Its three parts are the Next Defense loadout strip, the Skill Library on the left, and the selected skill's detail on the right. Use the game's existing wordmark, rank badge, medal icon, skill illustrations, parchment surfaces, gold borders, evergreen controls, and heading and body typefaces. Use live account values in place of the mockup's example values.

1. Place the three loadout slots above the library. Render the owned skill icon, name and Roman rank on each filled slot, and a visible Replace button. Empty slots show Add skill. The slot picker lists only owned skills absent from the draft loadout. A filled slot may also be cleared. Choosing an item replaces just that slot and neither spends medals nor saves the draft. Keep the 0–3 filled count visible. Save Loadout commits the draft through the existing profile API. Indicate unsaved changes, preserve the draft on failure, and retain the existing Save / Discard / Cancel choice when navigating away. Changes apply to the next new defense.
2. Place a compact, single-column catalogue under Skill Library. All, Owned, and Can buy filter the existing catalogue. Can buy uses the same eligibility rules as the purchase button. Use one tap target per row with illustration, name, owned rank and concise acquisition/equipment state. A skill that requires a higher military rank remains inspectable with the exact requirement visible. Keep all eleven skills discoverable through the list, and preserve selection and scroll position during ordinary in-place updates.
3. In the detail panel, show the selected illustration, name, type and gameplay explanation. Present ranks I, II and III as three readable tiles in order. Label owned ranks, highlight the next rank the player can buy, and show military requirements or the prior-rank prerequisite for locked ranks. Use the actual per-rank gameplay values, including separate gameplay resource costs. Show the current medal balance and the projected balance after an eligible purchase. Use one primary Unlock / Upgrade button with the actual medal price. If blocked, explain rank, medal or connection requirements. Fully upgraded skills show completion.
4. Keep Equip skill as a separate secondary action. For an owned skill with space, add it to the draft. With three occupied slots, ask the player which skill to replace. For an already equipped skill, show its equipped state. Buying a rank updates the balance and rank tiles immediately from the server response, retains the selection, and never implicitly changes slot membership. Keep account gating, server validation and skill mastery rewards on the existing API.
5. Preserve the Commander tabs and shared game navigation. On desktop and iPad, place the library and detail side by side. On narrower screens, stack sections, bring the detail into view when a skill is chosen, and provide a return to the library. Keep touch controls at least 44 CSS pixels, text wrapping cleanly, visible keyboard focus, and native dialog escape and focus restoration. Use the actual game assets rather than baking UI text or buttons into the mockup image.
6. Validate with a local fixture that covers empty, partial and full loadouts, cancel and replacement, saving, rank locks, insufficient medals, successful unlock and upgrade, and a stressed batch of taps. Verify the saved loadout remains separate from its pending selection. Check desktop, iPad landscape and portrait, and phone layouts, then pass the current test suite and publish the frontend through the existing production pipeline. Keep the design gallery local.
