# Original-reference UI portraits

These 136 UI pictures are integer rectangle crops of the 107 immutable illustrations mapped by the approved October 16 handoff. No model rendering, image generation, repainting, mirroring, recoloring or runtime-file resampling was used. All original source rasters and existing model-render portrait assets remain unchanged.

`crop-plan.json` records the selected rectangles and per-identity review. The runtime `public/assets/ui/reference-portraits/manifest.json` records source hashes, original dimensions, rectangles, chosen views, output dimensions and hashes. The six contact sheets and `index.html` present all 136 named outputs in English. Contact-sheet thumbnails are resized review derivatives; the runtime PNGs contain the exact unscaled source pixels.

The agent inspected every labelled contact-sheet identity, all nine shared or exceptional champion sources, and full sources for crop exceptions. This is visual implementation review, not a new human approval or physical iPad/Safari certification. Frost Knight and Elven King retain tiny source-caption fragments at the upper edge because their complete sword/antler silhouettes overlap the neighboring caption's vertical range. Preserving original pixels and the full subject takes precedence over erasing source material. Orc Crystal Phalanx uses the complete FRONT view; Orc Ash Executioners uses the complete LEFT view to avoid the neighboring caption while preserving its entire axe.

Regenerate with the bundled Pillow Python runtime and `tools/build-reference-portraits.py`. `tools/plan-reference-portrait-crops.py` only suggests rectangles for unreviewed six-view entries; it preserves approved/manual rectangles. Verify independently with `tools/verify-reference-portraits.py`, which reads every source/output and compares all decoded crop pixels. The checks do not modify any runtime/source files.

`ui/reference-portraits.js` exports `referencePortrait`, `referenceDefenderPortrait`, `referenceEnemyPortrait` and `referencePortraitImageMap`. URLs use `siteUrl` and an independent UI revision. Unknown identities and invalid ranks return `null`; catalogue creation performs no fetch, preload or image construction. The image map has existing `family:rank`, `family` and `enemy:host_NN` keys. Merge it into the existing thumbnail map to retain wall imagery. Use contain fitting for the different subject aspect ratios.

The portrait visibility observer gates both defender and enemy images in the new namespace by the current URL/request generation. Its legacy defender-only behavior remains intact for existing model tools. Targeted tests cover all exact identities, rank rejection, base paths, immutable inputs/output hashes, unique shared-board subjects, delayed decoding, enemy/rank swaps and stale completion failures. Integrated game browser, full-suite and publication gates belong to the release owner.
